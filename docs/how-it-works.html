How CEWP works — and how it compares to other decentralized meshes

Six people and one agent share one mesh of signed rows. Each sees a view of the same rows, folded through their own standing, and each view generates a queue: exactly the actions the admission door would accept from them now. Nothing here is a list of buttons: the queue is the door run forwards. Existing technology, in a new architecture.

Queue for —

The rule, from the CIRIS Constitution 4.5.13: for an object, the node holds its family, its lifecycle state and the person's standing toward it; the family's transitions come from the family model; the queue is the enabled transitions, one item each, and the door admits by the same predicate. Proved in formal/event_lifecycle; the transitions are rows of manifests/transitions.json; the story is tools/mesh_story.py.

Nothing here is a new technology. Signed rows, Merkle trees, hybrid post-quantum keys, cover traffic, deterministic encodings, CBOR and COSE have all existed for years.

What is new is the arrangement: one table that is both the admission door and the source of every action a person is offered, folds every node computes identically, and a constitution whose rules are tied to the code and proofs that back them. Below, eleven problems decentralized networks have failed on, each with the mechanism, the existing technology it uses, and what remains.

problem 1

Two copies of the rules

Every app keeps its rules twice: in the code that draws the buttons and in the code that refuses the request. They drift, and the drift is where authorization bugs live.

One table, the family model, decides both. The queue a person sees is the admission door run forwards: the transitions of the object's family enabled for their standing. Proved sound and complete.

With: A generated manifest, CDDL schemas, Lean, plain JSON.

What remains: The model is small and abstract today; the transitions table is derived, with its gaps marked.
problem 2

Moderation without a department

Federated networks centralize moderation in an operator or leave it to whoever runs a server.

A delegable duty, never a platform role. A moderator acts alone on content, never on membership. Anyone may flag; the live majority decides when no moderator acts. A room that loses its moderator locks and elects one by its own signatures.

With: Signed delegation edges, order-free folds, instant runoff over signed ballots.

What remains: What a room does without is a legally reachable person behind the duty when its moderator is anonymous.
problem 3

Identity without a registrar

Either a registry decides who exists, or anyone mints unlimited identities and outvotes the real ones.

Nobody is admitted without their own yes, and no single vote admits. Trust is each reader's own set of roots. One person, one vote, however many devices. Relays are bounded per sender by the sender's own contacts.

With: Hybrid signatures, a self roster per person, delegation with scope and term, a founders' ceremony.

What remains: A person whose only relay contact is hostile is exposed; the seat is the guard of last resort.
problem 4

Consent in a replicated store

Once a statement replicates it cannot be unsaid, and systems pretend it can or give up on consent.

Rows are forward-only. A withdrawal is a boundary, not a deletion. Nothing is written on anyone's behalf. Folds are order-free, so offline disagreement resolves the same way everywhere.

With: Append-only signed rows, permutation-invariant folds, per-item durability.

What remains: Receipts signed by others cannot be re-signed in a migration; legacy forms are accepted only before the cutover.
problem 5

Who talks to whom

Encryption hides content and leaks the graph. Onion routing breaks under a global observer.

CC §5.4.3 budget classes & 1-hop shaped links separate device shaped classes (server 7,000 B/s, home 2,800 B/s, phone-wifi 1,400 B/s, phone-cellular 350 B/s, L≤8, ρ=0.5, W=600 s / 3,600 s cellular), seat shaped links (33,000 B/s between serve seats), and unshaped ordinary / CC §6.1.6 deterministic-alm member relay trees over sealed chunks (distinct from CC §5.3.3.2's no-SFU-relay-role). A shaped link is one direct hop, never forwarded; peers without a direct path carry on ordinary links. Anonymity is a dedicated identity behind a sticky guard from your own contacts, walking 15,296 B X-Wing onion packets across shaped links by replacing cover frames at +0 extra wire bytes.

With: Poisson cover in the mixnet lineage (Tiers.lean: each_home_adds_seven, reach ≠ capacity), per-hop X-Wing post-quantum encapsulation, derived addresses, and direct IPv6 / punched UDP reachability (leviculum#100, #101).

What remains: Which links exist is never hidden; relays do not mix at today's load; a sleeping phone is exposed to a room insider.
problem 6

Post-quantum from the first key

Retrofitting post-quantum cryptography is a migration no network has finished.

Every signature and key exchange is hybrid from the first key: one composite signature, one hybrid KEM. The next signed object is CBOR with COSE, a statement any transparency log can register.

With: ML-DSA-65 with Ed25519 as the IETF composite, X-Wing, COSE, SCITT, COSE receipts.

What remains: No external audit yet, by Verify's own account.
problem 7

Twenty-nine languages, no release cycle

Localization lives in each client's binary and ships at app-store speed.

Every string is served by the node for the requested locale by a stable id. Clients hold no copy, so a new language reaches every surface, browser and firmware node included, with no release.

With: Text references in the view and the queue; one id namespace.

What remains: The migration is card by card; a node that lacks a locale serves the source language, marked.
problem 8

Governance at ten thousand members

Fractional quorums become unreachable as a group grows, or someone picks the electorate.

Votes count against the expected-active base, a member-only count from a secret-shared census under a ratchet that silencing cannot game. Every door runs one decision shape, five numbers published as data.

With: Secret sharing to two drawn members, integer folds, a published policy table, a model-checked machine.

What remains: The base lands with the substrate's next version; small rooms count their whole roster today.
problem 9

Transparency without a transparency service

Audit logs are run by someone who can be compelled or captured.

Every build, licence and stream has its own Merkle log, witnessed by cosignatures; receipts are standard; every rule is tied in a public register to its code, test or proof, or says nothing backs it yet.

With: RFC 6962 and 9162 trees, witness cosignatures, COSE receipts.

What remains: Witnesses are few while the network is small.
problem 10

Coordination without a coordinator

Fan-out trees, relay choice and leader choice need a coordinator, and the coordinator is the point of capture.

Determinism replaces coordination. Every node computes the same relay tree, layer deal, vote count and moderator seat from the same signed inputs, hardened so one lie cannot become a universal one.

With: Pure integer functions over signed inputs, checked by vectors.

What remains: The live media tree does not yet run the verified function; the register says so.
problem 11

The protocol itself

Whoever controls the specification controls the network.

The constitution is forkable, its amendment process entrenched behind the quorum it describes, authority with a named steward until a measured scale, and tooling that refuses to build when text and evidence disagree.

With: A public register, machine-checked text, formal models in CI.

What remains: The scale gate is a bet, stated as one.

One sentence

A client renders two served shapes, the view and the queue, holds the keys of its deployment and no policy, and the queue is the admission door run forwards.

The view

One object's rows and the atoms the node folded from them through the person's own trust set, each atom with its provenance: the rows it read and the rule it ran. The record and the state are one thing seen twice.

view = { object: {family, id, scope}, locale, rows: [* row-ref], atoms: [* atom], ? standing }
atom = { name, value, label: text-ref, provenance: { rows: [* id], rule: cc-decimal, kind: wire / by_rule / not_sent } }
text-ref = { id, text, ? params, ? lang }

The queue

The items awaiting the person's hand: a context, facts with provenance, a governance policy row, options with a benefit and a downside that are never empty, the rows each would sign, and an impact derived from the family model. Four kinds: choice, act, entry, notice. Consent is not a kind.

choice-item = { id, kind, context, ? facts, policy, ? options: [* option], ? default, required, ? answer }
option = { value, benefit, downside, writes: [* {family, verb, scope}], impact: {moves, to, direction, undo}, available }
answer = { state: served / held / signed / deferred / changed, ? value, ? ranking, shown_digest, ? rows }

How the view makes the queue

For an object, the node holds its family, its lifecycle state and the person's standing. The family's transitions (verb, from, to, roles, policy, widens) come from the family model. The queue is exactly the enabled transitions, one item each; the door admits by the same predicate. A stranger sees nothing; an answered item leaves the next view; a widening item is confirmed before it is signed.

queue(view, standing) = [ item(t) | t in transitions(view.family), t.from = view.state, t.roles meets standing ]
admits(view, standing, t) = (t.from = view.state) and (t.roles meets standing)      -- the same predicate

Localization, and the way there

Every string is a node-served text reference for the requested locale; the client holds no copy. While a node lacks a locale it serves the id with source-language text, marked, and a consumer may overlay its own bundle by id; the difference between served ids and held strings is the measured distance, closed card by card.

The next signed object

CBOR with COSE, aligned with SCITT: one COSE_Sign1 per signer, issuer and subject claims, the composite ML-DSA-65 with Ed25519 construction, composite keys with thumbprint ids, deterministic encoding, content-addressed statement ids, COSE receipts over RFC 9162 trees. Every row signed under the earlier object verifies as itself.
